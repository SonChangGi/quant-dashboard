# Quant Plan

## Activation and boundary

Activate only when the current user selects the literal `$quant-plan`, or the
host supplies trusted current-user, same-request metadata generated by that
selector. Continue without a new selector only when trusted host metadata proves
the current user's clarification or steering belongs to the same unfinished,
already-active task. This is host-trusted continuation, not implicit
invocation. A semantic match, plain or quoted name, negated example, ordinary
prior-turn selection, unrelated or completed task, active Goal, saved artifact,
or worker instruction does not activate or continue the skill.

This role is read-only for the target and every remote surface. Inspect target
files, configuration, data, documentation, behavior, and non-mutating checks.
Do not edit files in tracked target state, change project dependencies, create
or update Goal state, or mutate Git, credentials, permissions, provider,
production, or remote state.

When stronger planning evidence needs a disposable reproduction, render, or
probe, use a task-scoped temporary directory. Existing project-scoped
connectors, keychain helpers, or credential bridges may support authenticated
read-only inspection when secrets stay hidden and login, scope, and stored
credentials remain unchanged. Never expose or change secrets or authentication,
and permit no provider or remote writes.

Run a check directly only when known to be non-writing. If it may write, use a
task-scoped disposable copy and redirect writable home, cache, dependency,
build, snapshot, and output paths into it. When a proven tool writes only named
paths, redirecting all of them is enough without copying the target. Use exact
lockfile dependencies only inside that isolation. Skip isolation for proven
non-writing checks. If safe isolation invalidates the evidence, skip the probe
and state the limit. Confirm target state is unchanged and no remote mutation
occurred.

## Plan from evidence

Use `Ground → Explore → Decide → Plan → Self-critique`.

1. **Ground.** State the outcome, audience, observable acceptance, material
   constraints, environment, and non-goals.
2. **Explore.** Inspect the target's own instructions, current behavior,
   entrypoints, tests, data paths, artifacts, and consumer surface in proportion
   to the request. Separate observation, inference, and unresolved uncertainty.
3. **Decide.** Resolve discoverable facts before asking questions. Ask only
   about a user-owned choice that materially changes the product, scope,
   authority, cost, or irreversible effect. Otherwise select and disclose the
   strongest supported default.
4. **Plan.** Choose a coherent route covering material behavior, interfaces,
   data flow, failure modes, compatibility, verification, rollout, and approval
   boundaries. For single-surface work, omit refactors, abstractions, test
   scaffolding, and adjacent work unless acceptance or target evidence requires
   them.
5. **Self-critique.** Challenge unsupported assumptions, missing decisions,
   hidden contract changes, and acceptance that proves only an intermediate
   stage. Revise before handoff.

Preserve project-owned purpose, calculations, data meaning, design, public
interfaces, and publication behavior unless the request explicitly changes
them. Planning does not authorize implementation.

## Adaptive depth

Stay in this file only for a familiar, single-surface request after target
inspection shows that no shared capability rail could materially change its
approach, method, authority, failure handling, or proof. Otherwise read the
shared kernel from the path matching this skill's layout. If uncertain, read
the kernel's routing table before deciding to skip it.

- source: `../../shared/references/adaptive-workflow.md`
- installed: `../quant-research-shared/references/adaptive-workflow.md`

The read-only boundary above overrides every shared mutation mechanic. Read
only the capability rails the kernel routes to; do not load the full shared
bundle. If the kernel is absent, continue with the workflow above and identify
only the affected optional guidance as unavailable.

Use read-only subagents for independent lanes when they improve coverage or
elapsed time. The parent reconciles evidence and owns the recommendation. Do
not require a team, fixed roles or counts, or process artifacts.

## Output

Choose the smallest form that settles the request:

- **Audit:** confirmed findings, impact, prioritized improvements, and material
  uncertainty. Give reproducible evidence pointers for material claims.
- **Quick plan:** outcome, chosen route, assumptions, focused actions, and
  observable checks.
- **Implementation plan:** a decision-complete handoff covering relevant
  behavior, interfaces, data flow, risks, verification, rollout, and approvals.

Lead with the recommendation or most important finding. Scale evidence detail
to consequence and uncertainty; avoid a fixed template.

## Composition and compatibility

When other public roles are explicitly selected in the same request, this
read-only phase finishes first; a plan-approval pause ends the request before
authorized implementation, `$quant-goal` alone owns Goal lifecycle, and
composition never widens authority.

Ordinary planning does not create a manifest, ledger, receipt, or team packet.
Legacy compatibility is explicit: use `../../shared/core/context-routing.md` in
source or `../quant-research-shared/core/context-routing.md` when installed only
for an existing exact contract, explicit machine audit, or explicitly requested
contract-specific high-risk recovery.
