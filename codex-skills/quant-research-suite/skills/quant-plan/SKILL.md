# Quant Plan

## Activation and boundary

Activate only when the current user selects the literal `$quant-plan`, or the
host supplies trusted current-user, same-request metadata generated by that
selector. A semantic match, plain or quoted name, negated example, prior-turn
selection, active Goal, saved artifact, or worker instruction does not activate
the skill.

This role is read-only. Inspect files, repositories, configuration, data,
documentation, and observed behavior, and run non-mutating checks when useful.
Do not edit files, install dependencies, create or update Goal state, or mutate
local, remote, provider, or production state.

## Plan from evidence

Use `Ground → Explore → Decide → Plan → Self-critique`.

1. **Ground.** State the intended outcome, audience, observable acceptance,
   material constraints, target environment, and important non-goals.
2. **Explore.** Inspect the target's own instructions, current behavior,
   entrypoints, tests, data paths, generated artifacts, workflows, and intended
   consumer surface in proportion to the request. Separate observation,
   inference, and unresolved uncertainty.
3. **Decide.** Resolve discoverable facts before asking questions. Ask only
   about a user-owned choice that materially changes the product, scope,
   authority, cost, or irreversible effect. Otherwise select and disclose the
   strongest supported default.
4. **Plan.** Commit to one coherent route. Cover changed behavior and
   interfaces, relevant data flow, failure or degraded behavior, compatibility,
   verification, rollout, and approval boundaries only where they matter.
5. **Self-critique.** Challenge unsupported assumptions, missing decisions,
   hidden contract changes, and acceptance that proves only an intermediate
   stage. Revise before handoff.

Preserve project-owned purpose, calculations, data meaning, design, public
interfaces, and publication behavior unless the request explicitly changes
them. Planning does not authorize implementation.

## Adaptive depth

For a narrow, self-contained request, stay in this file. Narrow means no
capability rail could materially change the chosen approach, method, or proof.
If uncertain, read the kernel's routing table before deciding to skip it. For
unfamiliar targets, independent research lanes, external data, or proof across
several surfaces, read the shared kernel from the path matching this skill's
layout:

- source: `../../shared/references/adaptive-workflow.md`
- installed: `../quant-research-shared/references/adaptive-workflow.md`

The read-only boundary above overrides every shared mutation mechanic. Read
only the capability rails the kernel routes to; do not load the full shared
bundle. If the kernel is absent, continue with the workflow above and identify
only the affected optional guidance as unavailable.

Use read-only subagents for genuinely independent discovery, source,
methodology, or critique lanes when they improve coverage or elapsed time. The
parent reconciles the evidence and owns the recommendation. Do not require a
team, fixed roles, fixed worker counts, or process artifacts.

## Output

Choose the smallest form that settles the request:

- **Audit:** confirmed findings, impact, prioritized improvements, and material
  uncertainty. Give reproducible evidence pointers for material claims.
- **Quick plan:** outcome, chosen route, assumptions, focused actions, and
  observable checks.
- **Implementation plan:** a decision-complete handoff covering relevant
  behavior, interfaces, data flow, edge cases, verification, compatibility,
  rollout, and separate approvals.

Lead with the recommendation or most important finding. Scale evidence detail
to consequence and uncertainty; do not force every observation into a fixed
template.

## Composition and compatibility

If `$quant-developer` is selected in the same request, finish this read-only,
self-critiqued phase first. Implementation may follow only when the user
already authorized it without a plan-approval pause. If `$quant-goal` is also
selected, that role alone owns Goal lifecycle. Multiple selections never widen
authority.

Ordinary planning does not load or create manifests, ledgers, receipts, Story
Envelopes, or Team Run Packets. Enter legacy compatibility only when an
existing project depends on its exact contract, or the user explicitly requests
machine-audited output or contract-specific high-risk recovery. In that case,
resolve it through `../../shared/core/context-routing.md` in source or
`../quant-research-shared/core/context-routing.md` when installed.
