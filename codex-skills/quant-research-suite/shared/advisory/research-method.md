# Advisory: research method

1. Restate the real decision and the evidence needed.
2. Inspect local code/runtime before assuming the architecture.
3. Search primary, authoritative, and current sources for unstable or externally
   referenced facts.
4. Record source, finding, limitation, confidence, and the decision it supports.
5. Compare viable options using the same criteria.
6. Distinguish immutable safety/contract constraints from preferences and
   reversible defaults.
7. End with a traceable recommendation: finding → proposed change → verification.

Research is read-only unless the user separately asks to implement. Do not
create project manifests, goal state, commits, releases, or cloud resources as a
side effect of planning.
