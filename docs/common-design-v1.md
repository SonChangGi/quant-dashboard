# Quant Research 공통 디자인 v1.2

> 최신 최우선 규범과 복사용 실행 프롬프트는 [Quant Research Web Design Prompt](web-design.md)입니다. 이 문서는 DRAM·Fear & Greed 파일럿에서 확립한 정보 구조·차트 상태·보호 경계의 근거 문서로 유지합니다.

## 상태와 적용 범위

- 버전: `1.2.0`
- 기준일: `2026-07-23`
- 상태: 완료된 프로젝트들의 개선 결과에서 공통 시각 밀도와 상호작용 규칙을 추출한 기준
- 검증 이력(비규범):
  - DRAM React/Vite 파일럿: `SonChangGi/dram-price` main `ae5edd8` (PR #2)
  - Fear & Greed 정적 프론트엔드 파일럿: `SonChangGi/fearNgreed` main `d052e30` (PR #5, #6)
- 적용 대상: Quant Research Hub와 연결된 각 프로젝트의 공개 리서치 페이지

이 문서는 특정 프레임워크나 공용 컴포넌트 패키지가 아니라 **정보 구조, 시각 밀도, 차트 동작, 접근성, 검증 방식**을 고정한다. 각 저장소는 React/TypeScript 또는 정적 HTML/CSS/JavaScript 등 현재 구조를 유지하면서 이 계약을 구현한다.

v1.2는 어느 한 공개 화면을 복제 기준으로 지정하지 않는다. DRAM에서 확인한 간결한 시각 밀도, Fear & Greed와 ETF Tracking에서 검증한 차트 탐색처럼 각 프로젝트의 장점을 근거로 삼되, 규범은 **공통 정보 위계·타이포그래피·설명 밀도·탐색 셸·접근성**이다. 각 프로젝트는 고유한 분석 흐름, 결과 구조, 차트, 표와 기존 청색 중심 색감을 유지하면서 같은 제품군으로 느껴지는 통일성을 구현한다.

## 목적

1. 사용자가 첫 화면에서 결론 또는 최신 핵심값, 데이터 기준일, 핵심 차트를 먼저 이해하게 한다.
2. 반복 설명과 운영 상세는 줄이되, 결과를 사용할 수 없는 상태는 숨기지 않는다.
3. 차트 안에서 선택 날짜와 정확값을 확인하고 원하는 계열을 명확하게 강조하게 한다.
4. 차트 탐색이 데이터·분석 결과를 몰래 바꾸지 않게 한다.
5. 모바일·키보드·라이트/다크 테마에서 같은 의미를 유지한다.

## 보호 경계

공통 디자인 적용만으로 다음 항목을 변경하지 않는다.

- 수집기, 분석·전략 계산, 방법론, 임계값, 거래 규칙
- 공개 JSON 스키마, 정밀도, 날짜 의미, 데이터 권리
- GitHub Pages URL과 자동화·배포 흐름
- fail-closed 검증과 `unavailable`, `blocked`, `degraded`, `stale` 상태
- 프로젝트별 단위, 벤치마크, 시계열 간격, 포지션·체결 의미
- 프로젝트별 결과 구조, 고유 차트·표 구성과 승인된 기존 색 토큰·primary·의미색

FastAPI, Supabase, Vercel, React 또는 TypeScript 전환은 별도 아키텍처 결정이다. 공통 디자인 v1의 채택 조건이 아니다.

## 1. 결과 우선 정보 구조

공개 페이지는 다음 순서를 기본으로 한다.

1. 페이지 정체성과 현재 운영 상태
2. 데이터 기준일과 핵심 결과 또는 최신 대표값
3. 사용자가 가장 자주 확인할 핵심 차트
4. 필요한 입력·필터·분석 설정
5. 정확값 표, 출처, 운영 내역, 방법론

프로젝트 특성상 설정이 결과보다 먼저 필요하면 전체 설정 폼 대신 **현재 적용값 한 줄 요약**만 먼저 둔다. 전체 컨트롤은 기본 닫힘 상태로 제공할 수 있다.

### 첫 화면의 필수 요소

- 페이지 제목과 핵심값만으로 의미가 분명하지 않을 때만 짧은 설명 한 문장
- 현재 상태와 데이터 기준일
- 핵심 결론 또는 최신 대표값
- 핵심 차트나 그 차트로 바로 가는 주 동작
- 사용자가 다음에 할 수 있는 명확한 동작 1~2개

## 2. 텍스트 밀도와 단계적 공개

- 같은 제한·출처·방법 설명을 Hero, 카드, 차트, Footer에 반복하지 않는다.
- 결과 해석에 반드시 필요한 단위·기간·정책은 결과 옆에 짧게 유지한다.
- 공급자 상세, 자동화 로그, 긴 계산 과정, 원본 JSON 링크는 접힌 상세 또는 Footer로 이동한다.
- 운영 상태는 `상태 + 기준일`을 먼저 보여 주고 상세 사유는 한 곳에서 펼치게 한다.
- 일반적인 비상업적 연구 문구는 한 번 명확하게 표시한다.
- 데이터가 실제로 사용 불가능하거나 잠정치인 경우에는 핵심 상태를 접지 않는다. 긴 원인 설명만 접는다.
- 핵심 차트의 상시 메타는 해석에 필요한 3~4개 묶음 이내를 권장한다.
- 사용자의 해석이나 다음 행동을 바꾸지 않는 구현 설명은 공개 화면에서 제거한다.
- `Python이 생성한 값을 그대로 표시`, `표시 설정은 저장된 결과를 다시 계산하지 않음`처럼 보호 경계를 설명하는 문구는 UI가 아니라 코드·테스트·개발 문서에 둔다.
- badge·제목·숫자가 이미 전달한 사실을 문장으로 다시 설명하지 않는다. 제목과 컨트롤만으로 의미가 분명한 helper 문장도 생략한다.
- 중립 또는 신호 없음 상태는 `추가 신호 없음`처럼 짧게 한 번만 표시한다. `허용구간 안에 있어 방향을 추정하지 않습니다` 같은 중립 사유를 카드와 표의 각 행에 반복하지 않는다.
- 행별 `message`나 `actionExplanation`은 짧은 분류·동작 label이 있으면 기본 화면에 출력하지 않는다. 필요한 방법론·출처·제한은 한 곳의 접힌 상세에만 둔다.

텍스트를 줄이는 기준은 글자 수 자체가 아니라 **같은 판단에 필요하지 않은 반복을 제거했는가**이다.

### 2.1 공통 타이포그래피와 세로 밀도

아래 값은 프로젝트군의 기본 권장 범위다. 픽셀 단위 복제가 아니라 동등한 역할의 글자가 비슷한 크기·굵기·행간과 강조 수준을 갖게 하는 것이 목적이다.

- 기본 본문은 `15px`, `line-height: 1.55`를 기준으로 하고 일반 본문·표·카드 설명은 대체로 `13~15px` 범위에서 구성한다.
- 보조 metadata는 `11~12px`를 사용할 수 있다. 핵심 상태, 조작 label, 오류 대응처럼 판단이나 행동에 필요한 글자는 `12px`보다 작게 만들지 않는다.
- 페이지 제목은 `clamp(2rem, 4vw, 3.25rem)`, 섹션 제목은 `clamp(1.35rem, 2.3vw, 1.8rem)`, 카드 제목은 약 `14px`, 대표값은 `1.45~2rem`을 상한 기준으로 삼는다. 더 큰 글자가 필요하면 도메인상 이유를 기록한다.
- 본문은 `400~500`, 조작·label은 `600~700`, 제목·대표값은 주로 `700`을 사용한다. `800` 이상은 브랜드, eyebrow 또는 한 화면의 소수 핵심 강조에만 쓰고 카드 안의 모든 제목·값·badge를 동시에 진하게 만들지 않는다.
- 한 카드나 한 행에서 기본적으로 하나의 정보만 가장 진하게 강조한다. `strong`의 상속이나 전역 규칙으로 다수 문장을 일괄 bold 처리하지 않는다.
- 카드 padding은 대체로 `18~30px`, 주요 section 간 세로 간격은 `18~28px` 범위를 우선 검토한다. 빈 설명 문단과 과도한 heading margin으로 페이지 길이를 늘리지 않는다.
- 가능하면 `1440×900` 첫 화면에서 상위 메뉴, 페이지 정체성, 핵심 상태·결과와 핵심 차트의 시작 부분까지 읽히게 한다. 필수 분석 입력이 먼저 필요한 프로젝트는 예외를 기록한다.

글자 크기가 작다는 이유로 불필요한 설명을 남겨 두지 않는다. 작은 disclaimer, 제한, 규제, 구현 설명도 사용자의 현재 판단에 필요하지 않으면 삭제하거나 하나의 기본 닫힘 `운영 상세`로 이동한다.

## 3. 상태와 날짜 모델

페이지는 운영 건강과 리서치 의미를 하나의 색이나 문구로 합치지 않는다.

- **운영 상태**는 수집·검증·신선도·출처의 사용 가능성을 뜻한다.
- **도메인 상태**는 가격 방향, 신호, 포지션처럼 프로젝트가 계산한 의미이며 모니터링 페이지에는 없을 수 있다.
- 화면 표현은 `정상`, `주의해서 사용`, `사용 불가`의 세 수준으로 정규화할 수 있지만, 저장소의 원래 enum과 원인은 그대로 보존한다.
- 필수 계약이 깨지면 숫자를 만들지 않고 사용 불가로 닫는다. 선택적 자동화·보조 신호만 실패하면 검증된 본 결과는 유지하고 보조 상태만 낮춘다.

날짜 역시 서로 다른 역할을 하나의 “최신일”로 합치지 않는다.

| 역할 | 의미 | 표시 규칙 |
| --- | --- | --- |
| 데이터 기준일 | 공개 데이터 전체의 최신 유효 관측일 | 상단 상태 영역에 항상 표시 |
| 평가 종료일 | 전략·사건·모형 결과가 계산된 마지막 날짜 | 해당 분석이 있을 때만 표시 |
| 차트 선택일 | 사용자가 현재 탐색 중인 날짜 | 차트 값 카드와 선택 가이드에 표시 |
| 수집·생성 시각 | 파일이나 자동화가 생성된 시각 | 운영 상세에 표시 |
| 필터 적용 범위 | 현재 차트에 실제 포함된 시작·종료일 | 차트 메타에 표시 |

프로젝트에 존재하지 않는 날짜 역할을 새로 만들지 않는다. 가격 모니터처럼 전략 평가 종료일이 없는 프로젝트와 전략 평가·차트 탐색 날짜를 모두 가진 프로젝트의 날짜 모델은 서로 다를 수 있다.

## 4. 핵심 차트 계약

이 절의 상호작용은 기존에 해당 기능이 있거나 도메인상 필요성이 확인된 비교 계열·날짜 축에만 적용한다. 공통 디자인만을 이유로 다중 계열이 없는 차트에 계열 선택을 새로 만들거나 날짜 축이 없는 차트에 날짜 탐색을 강제하지 않는다. 기본 계약은 기존 차트·표의 type·series·axis·legend·column·order를 보존하면서 가독성·겹침·접근성을 개선하는 것이며, 특정 프로젝트 형태로 재설계하는 것이 아니다.

### 4.1 계열 강조

- 비교 차트는 사용자가 강조할 계열을 이름이 보이는 버튼으로 제공한다.
- 고정된 강조 대상은 `aria-pressed`로 표현한다.
- hover와 keyboard focus는 임시 미리보기이며, 떠나거나 blur되면 직전 고정 상태로 돌아간다.
- click, tap, Enter, Space는 계열을 고정한다.
- 비활성 계열은 흐리게 표시하되 사라지게 하지 않는다.
- 강조는 명도·활성점·직접 라벨로 표현하며 색만으로 구분하지 않는다.
- 프로젝트에 따라 명시적 계열 선택 전에는 최신 선택일에 값이 있는 문맥 계열 하나를 기본 강조할 수 있다.

### 4.2 날짜 탐색

- hover는 임시 날짜 미리보기, click·tap은 날짜 고정으로 동작한다.
- 초기 고정일은 프로젝트의 의미상 종료일이며, pointer가 차트를 떠나면 직전 고정일로 돌아간다.
- `ArrowLeft`, `ArrowRight`, `Home`, `End`를 지원한다.
- 날짜 입력 또는 선택 컨트롤을 제공하고 휴장일·누락일은 가장 가까운 유효 관측으로 처리한다.
- `최신일로` 또는 `평가 종료일로` 버튼은 프로젝트가 명시한 날짜 역할로 정확히 복귀한다.
- 선택일은 세로 가이드와 활성 계열의 점으로 표시한다.

### 4.3 정확값 카드

차트 section의 보이는 영역 안에 다음 값을 유지한다.

- 차트 선택일
- 활성 계열의 전체 이름
- 정확값과 단위
- 해석에 필요한 짧은 문맥: 상태, 포지션, 체결 또는 관측 유무

정확값 readout은 기본적으로 plot 영역 밖의 정상 흐름 행에 배치한다. 선·점·신호·축·끝 라벨 위에 absolute overlay로 올리지 않는다.

- tooltip만 일시적으로 부유할 수 있다. plot·viewport 경계에서 위치를 바꾸고 활성 데이터나 끝 라벨을 가리키면 외부 readout으로 대체한다.
- custom readout이 있으면 같은 내용을 반복하는 SVG native title tooltip과 모든 시점의 상시 값 label을 함께 노출하지 않는다.
- 모바일 readout은 가로 스크롤 canvas 밖에 유지한다.
- 직접 끝 라벨을 사용하면 별도 gutter를 예약하고 라벨끼리 충돌하지 않게 정렬한다.
- 정확값 숫자는 원본 데이터 정밀도와 도메인별 표시 계약을 따른다.

### 4.4 탐색 상태의 격리

계열 강조, hover 미리보기, 차트 선택일은 **프레젠테이션 상태**다. 이 상태만 바꿀 때 다음 항목은 변하지 않아야 한다.

- 데이터와 분석 입력
- 결론·성과 카드·정확값 표의 공식 종료 결과
- 전략·신호·포지션·거래 계산
- URL query와 저장된 사용자 분석 설정

필터나 전략 입력을 실제로 바꾸는 컨트롤은 별도의 **분석 상태**로 취급하고, 적용 범위와 재계산 여부를 명시한다.

프레젠테이션 상태 격리는 구현·테스트 계약이다. 이를 매 section마다 사용자용 설명으로 반복하지 않는다.

### 4.5 데이터 정직성

- 서로 다른 단위·통화·의미는 facet 또는 패널로 분리한다.
- 관측이 부족하면 임의 보간이나 가짜 선을 만들지 않는다.
- 선택 날짜에 값이 없으면 `관측 없음`을 표시한다.
- 가격·수익률·지수·비중의 단위를 값과 축에 명시한다.
- 신호일과 체결일처럼 경제적 의미가 다른 사건은 도형·레이블·설명으로 구분한다.
- 정확값 표나 제한된 원시 관측 목록을 키보드·스크린리더 대안으로 제공한다.

## 5. 공통 탐색·테마 셸

- 프로젝트 메뉴의 기준 순서는 `Hub → Fear & Greed → Momentum → DRAM → Best Factor → ETF → SOX → Port`다.
- 위 8개 항목과 공개 URL을 공통 메뉴 registry로 취급한다. 완료된 일부 프로젝트나 현재 프로젝트와 Hub만 따로 하드코딩하지 않는다.
- 데스크톱에서는 8개 링크를 직접 보여 주거나 메뉴 자체 가로 스크롤로 제공하고, 좁은 화면에서는 펼침 메뉴를 사용할 수 있다. 어느 방식이든 사용자는 현재 페이지에서 8개 목적지에 접근할 수 있어야 한다.
- 공통 compact shell은 높이 약 `58px`, brand는 `14px`, 메뉴 글자는 `12px / 650`, 조작 영역은 최소 `44px`로 구성한다. 현재 항목은 soft-blue surface와 primary text로 구분하되 기존 프로젝트 색 토큰을 사용한다.
- 현재 페이지는 `aria-current="page"`로 구분하고, 메뉴는 좁은 화면에서 문서가 아니라 자체 영역만 스크롤한다.
- 본문으로 바로 가는 skip link를 첫 keyboard focus로 제공한다.
- 테마 저장의 기준 key는 `quant-research-theme`다. 기존 `quant-dashboard-theme`, `quant-calm-theme`, `dram-price-theme`는 읽은 뒤 기준 key로 옮기는 호환 입력으로만 유지한다.
- 테마 우선순위는 유효한 URL query → 기준/legacy 저장값 → system preference → light fallback이다. 사용자가 토글한 값은 기준 key에 저장한다.
- 공통 메뉴와 테마는 각 저장소가 자체 구현하며 다른 저장소의 런타임 파일을 직접 불러오지 않는다.

## 6. 반응형·접근성 계약

- 최소 검토 폭은 `390px`이며 문서 전체의 `scrollWidth`가 viewport를 넘지 않아야 한다.
- 차트, 표, 또는 의도된 카드 rail처럼 데이터 밀도가 높은 영역만 자체 가로 스크롤할 수 있다.
- 가로 스크롤 영역 밖에서도 차트 제목, 계열 선택, 정확값 카드를 확인할 수 있어야 한다.
- 주요 버튼과 입력은 최소 `44×44px` 터치 영역을 갖는다.
- 조작 label과 핵심 상태·차트 metadata의 계산된 글자 크기는 `12px`보다 작게 만들지 않는다.
- hover 없이도 같은 정보를 click·tap·keyboard로 확인할 수 있어야 한다.
- 차트는 이름·설명·단위를 텍스트로 제공하고 키보드 focus가 보여야 한다.
- SVG 내부에 개별 tab stop을 늘리지 않고 차트 frame을 하나의 keyboard 탐색 지점으로 제공한다.
- 계열은 색과 함께 선 종류, 마커 형태, 직접 라벨 중 하나 이상을 사용한다.
- 라이트·다크 테마 모두에서 본문, 축, 격자, 상태, focus ring이 읽혀야 한다.
- `prefers-reduced-motion`에서는 비필수 전환을 제거한다.

## 7. 시각 토큰과 구현 소유권

각 저장소는 다음 의미 토큰을 자체 기술 스택에 맞게 소유한다.

- 배경: `bg`
- 기본·상승 surface: `panel`, `surface`, `surface-raised`
- 본문·강조·보조 텍스트: `ink`, `ink-strong`, `muted`
- 경계: `line`, `line-strong`
- 주 동작: `primary`, `primary-strong`, `primary-soft`
- 상태: `success`, `warning`, `danger`, `neutral`
- 차트 배경: `chart-panel`

v1에서는 저장소 간 런타임 CSS·npm 패키지를 공유하지 않는다. 같은 의미를 각 저장소의 CSS 변수, React 컴포넌트 또는 정적 JavaScript로 구현한다. 이 방식은 한 저장소의 배포 실패가 다른 프로젝트를 깨뜨리는 것을 막는다.

기존의 밝은 중립 surface와 청색 accent 중심 색감은 유지한다. 각 프로젝트의 승인된 색 토큰을 하나의 프로젝트 값으로 일괄 교체하지 않으며, 공통화 대상은 색상값의 복제가 아니라 배경·본문·강조·상태 간 역할과 대비다.

## 8. 역사적 적용 사례의 도메인 차이(비규범)

아래 표는 파일럿에서 서로 다른 분석 의미를 보존한 근거이며 후속 프로젝트가 복제해야 할 화면 사양이 아니다.

| 항목 | DRAM | Fear & Greed |
| --- | --- | --- |
| 핵심 결과 | 실제 대표 가격 6개와 운영 상태 | 선택 기간 결론, 평가 종료일 신호, 전략 결과 |
| 날짜 | 데이터 기준일, 필터 범위, 수집 시각, 차트 선택일 | 데이터 기준일, 평가 종료일, 차트 선택일 |
| 차트 구성 | 종류·통화·지표별 facet, facet당 최대 5개 제품 | KOSPI 가격·신호/체결·전략 성과 3패널 |
| 값 형식 | 통화와 가격 정밀도 유지 | KOSPI `pt`, 전략·매수보유 signed `%` |
| 상세 데이터 | 10개 우선, 최대 50개 관측을 표/카드로 제공 | 최근 통합 관측과 전략·거래 표를 접어서 제공 |
| 모바일 스크롤 | 차트와 의도된 최신가격 rail이 자체 스크롤 가능 | 차트 canvas만 자체 가로 스크롤 |
| 분석 결과 | 가격 관측이므로 신호·수익률을 새로 만들지 않음 | 선택일 탐색이 백테스트 종료 결과를 바꾸지 않음 |

공통 디자인은 위 예외를 제거하는 규칙이 아니라, 서로 다른 도메인을 같은 읽기 방식으로 제공하는 규칙이다.

## 9. 검증 게이트

프로젝트가 공통 디자인 v1을 채택했다고 판단하려면 다음을 확인한다.

1. 결과·기준일·핵심 차트가 상세 설정과 긴 설명보다 먼저 읽힌다.
2. 데이터 사용 불가 상태는 눈에 보이며 상세 사유는 중복되지 않는다.
3. 계열 preview와 고정 선택이 구분되고 비활성 계열이 시각적으로 약해진다.
4. 날짜 탐색과 최신/평가 종료일 복귀가 동작한다.
5. 정확값 카드가 실제 차트 행과 같은 값·단위를 표시한다.
6. 프레젠테이션 상태가 분석 결과, URL, 저장된 분석 입력을 변경하지 않는다.
7. 공통 메뉴 순서·현재 페이지·skip link와 기준 테마 key/legacy migration이 일치한다.
8. `390px`에서 문서 가로 overflow가 없고 허용된 내부 영역만 스크롤한다.
9. 모든 주요 조작이 keyboard와 touch에서 가능하고 터치 영역의 가로·세로가 모두 `44px` 이상이다.
10. 라이트·다크 테마와 empty/degraded/unavailable 상태를 확인한다.
11. 저장소별 기존 계산·데이터 계약 테스트와 새 차트 상태 회귀 테스트가 통과한다.
12. 배포 시 CI·Pages 성공뿐 아니라 공개 URL에서 자산 버전, 날짜, 핵심 인터랙션을 다시 확인한다.
13. 데스크톱과 `390px` 라이트·다크 캡처에서 readout이 plot·축·직접 라벨과 겹치지 않는다.
14. 공개 DOM 문구 inventory에서 같은 설명의 중복이 없고, 중립 사유는 한 번 이하이며, 구현·재계산 관련 개발자용 설명은 노출되지 않는다.
15. 계산된 글자 크기·굵기 inventory가 공통 권장 범위와 위계를 따르고, `800` 이상 굵기가 화면 전반에 반복되지 않는다.
16. Hero 설명은 필요할 때만 한 문장, section helper는 제목·조작만으로 부족할 때만 한 줄이며, disclaimer·제한·운영 설명은 기본 화면에 반복되지 않는다.
17. 공개 상위 메뉴에서 8개 목적지와 현재 페이지가 확인되며 일부 프로젝트만 남는 축약 메뉴가 없다.
18. 기존 색 토큰, 분석 결과 구조, 고유 차트·표가 불필요하게 특정 프로젝트 구현으로 교체되지 않았다.

## 10. 나머지 프로젝트 확장 방식

- 한 번에 전체 저장소를 바꾸지 않고 프로젝트별 plan-goal로 진행한다.
- 각 프로젝트는 `현황 감사 → 보호 경계 고정 → 문구 inventory·중복 제거 → 결과 우선 재배치 → 핵심 차트·충돌 방지 → 테스트 → 모바일/테마 QA → 공개 검증` 순서를 따른다.
- 신규·후속 작업은 [Quant Research Web Design Prompt](web-design.md)를 시작점으로 사용한다. [v1 프로젝트 적용 프롬프트](common-design-v1-rollout-prompt.md)는 파일럿 이력으로만 참고한다.
- v1 계약과 충돌하는 도메인 요구는 억지로 맞추지 않고 이 문서의 허용 예외 표에 추가한다.
- 문구·타이포그래피·여백 같은 비파괴 개선은 v1.x로 갱신하고, 날짜·상태·차트 상태 모델을 바꾸는 변경은 v2 검토 대상으로 둔다.

## 11. 비규범 파일럿 근거

- DRAM: 결과 우선 카드, 접힌 고급 필터·운영 상세, active-series preview/pin, 선택일 가이드, 정확값 카드, 키보드·터치 차트, React 테스트
- Fear & Greed: 결과 우선 결론, 접힌 분석 설정·신호 계산, 데이터/평가/선택 날짜 분리, active-series preview/pin, 정확값 카드, 선택일 상태 격리, 정적 DOM·엔진 테스트

두 파일럿은 같은 런타임을 쓰지 않으면서 같은 사용자 계약을 구현했다. 따라서 v1의 재사용 단위는 TypeScript나 UI 라이브러리가 아니라 위의 구조·상태·검증 규칙이다.
