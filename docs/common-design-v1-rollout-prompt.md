# 공통 디자인 v1.2 프로젝트 적용 프롬프트

> 새 작업에는 6개 구현 사이트를 최우선 참조 스위트로 확장한 [Quant Research Web Design Prompt](web-design.md)의 복사용 실행 프롬프트를 사용합니다. 아래 내용은 v1.2 파일럿 적용 이력입니다.

아래 프롬프트는 v1.2 파일럿 당시 사용한 역사적 template이다. 새 프로젝트의 plan-goal은 [Quant Research Web Design Prompt](web-design.md)의 최신 복사용 실행 프롬프트로 시작한다.

## 복사용 프롬프트

```text
[프로젝트 이름]에 Quant Research 공통 디자인 v1.2를 적용해줘.

목표
- 분석 산출물을 바꾸지 않고 결과 우선, 낮은 텍스트 밀도와 명확한 시각 위계를 구현한다.
- 앞서 수정한 프로젝트들과 같은 제품군으로 느껴지는 통일성을 주되 어느 한 페이지나 컴포넌트를 복제하지 않는다.
- 공통화 대상은 정보 위계·타이포그래피·여백·설명 밀도·상위 메뉴·상호작용·접근성이며, 각 프로젝트의 분석 목적과 개성은 유지한다.

보호 경계
- Python 수집·분석·전략·임계값과 입력값에 따른 기존 결과 변화는 수정하지 않는다.
- 공개 JSON schema·정밀도·날짜 의미·데이터 권리와 workflow·GitHub Pages URL은 수정하지 않는다.
- 프론트엔드는 저장된 결과를 표시하고 탐색만 한다. 보호 경계는 코드·테스트로 증명하고 사용자 화면에서 반복 설명하지 않는다.
- 기존의 밝은 중립색·청색 primary 같은 Toss 계열 색감, 프로젝트별 의미색, 결과 구조, 차트 유형·패널·축·범례·계열과 표의 열·순서는 불필요하게 변경하지 않는다.

통일성의 범위
- 페이지 너비와 공통 shell, 결과 우선 정보 순서, 글자 크기·굵기 위계, 여백 밀도, 상태 표현, 상세 정보의 접힘 방식, theme·keyboard·mobile 품질을 맞춘다.
- 분석 입력, 결과 field, 핵심 차트 유형·계열, 표의 column과 도메인별 의미색은 유지한다.
- 픽셀 단위로 똑같은 화면을 만드는 것이 아니라, 서로 다른 분석 도구가 같은 Quant Research 제품군으로 읽히게 한다.

공통 타이포그래피와 밀도
- 기본 본문은 `15px / 1.55`를 기준으로 하고 일반 본문·표·카드 설명은 `13~15px`, 보조 metadata는 `11~12px` 범위를 우선 사용한다. 핵심 상태와 조작 label은 `12px`보다 작게 만들지 않는다.
- 페이지 제목은 최대 `clamp(2rem, 4vw, 3.25rem)`, 섹션 제목은 최대 `clamp(1.35rem, 2.3vw, 1.8rem)`, 카드 제목은 약 `14px`, 대표값은 `1.45~2rem`을 기준으로 한다.
- 본문·helper는 `400~500`, 조작·label은 `600~700`, 제목·대표값은 주로 `700`을 사용한다. `800` 이상은 브랜드·eyebrow 또는 한 화면의 소수 핵심 강조에만 사용한다.
- 한 카드나 한 행에서는 기본적으로 하나의 정보만 가장 진하게 표시한다. `strong` 전역 규칙이나 다수 badge로 화면 전체를 bold 처리하지 않는다.
- 카드 padding은 대체로 `18~30px`, 주요 section 간 세로 간격은 `18~28px`를 우선 검토한다. 같은 viewport와 같은 데이터에서 수정 후 기본 화면의 `scrollHeight`가 불필요하게 증가하지 않게 한다.
- 글자 크기·굵기와 설명 문구 때문에 페이지가 세로로 길어지지 않게 하고, 가능하면 `1440×900`에서 상위 메뉴·핵심 결과와 핵심 차트의 시작 부분까지 보이게 한다.

문구
- 사용자의 판단이나 다음 행동에 필요 없는 설명은 삭제한다.
- badge·제목·값이 이미 전달한 사실을 문장으로 다시 쓰지 않는다.
- Python, JSON/schema, 재계산 여부, 저장 결과 보존 같은 개발자용 구현 설명은 공개 UI에 노출하지 않는다.
- 신호 없음·중립 상태는 짧은 상태 한 번만 표시한다. 중립 사유와 행별 message/actionExplanation을 카드·표마다 반복하지 않는다.
- 작은 글자, caption, fine print도 반복 설명의 예외가 아니다. 규제·면책·제한·한계·출처·fallback·자동화 설명을 여러 section에 흩어 놓지 않는다.
- 규제·면책·제한·한계·출처·방법론·fallback·자동화 설명은 필요한 내용만 하나의 기본 닫힘 `데이터 · 출처 · 운영 상세`에 통합한다.
- 현재 결과의 사용 가능 여부를 바꾸는 warning·error만 기본 화면에 짧게 남기고 상세 원인은 `운영 상세`에 둔다.
- 제목·값·컨트롤만으로 의미가 분명하면 helper 문장을 만들지 않는다. Hero 설명은 필요할 때만 짧은 한 문장, section helper는 실제 해석을 바꿀 때만 한 줄로 제한한다.
- 동일 날짜·동일 대상의 중복 신호는 가능하면 한 visual item에 badge로 합치되 원본 데이터는 변경하지 않는다.

정보 구조
- 결론 또는 최신 핵심값 → 데이터 기준일·핵심 지표 → 핵심 차트 → 필요한 입력·필터 → 표·출처·방법론 순서로 구성한다.
- 정상 상태는 짧은 값으로 표시하고 긴 문장은 warning·error일 때만 사용한다.

공통 상위 메뉴
- 상위 메뉴는 `Hub → Fear & Greed → Momentum → DRAM → Best Factor → ETF → SOX → Risk Score → Port → Valuation → Kelly` 전체 11개 목적지를 최신 `quant-dashboard` registry와 같은 label·순서·URL로 제공한다.
- 완료된 일부 프로젝트 또는 Hub·현재 프로젝트만 하드코딩하지 않는다.
- 각 저장소가 메뉴 데이터와 markup을 자체 구현하며 다른 저장소의 runtime JavaScript·CSS를 직접 import하지 않는다.
- 공통 compact menu는 sticky shell 약 `58px`, brand `14px`, 메뉴 글자 `12px / 650`, 조작 영역 최소 `44px`로 구성한다. 현재 항목은 기존 primary 색의 soft surface로 구분한다.
- 현재 페이지 하나에만 `aria-current="page"`를 지정한다. `390px`에서도 접이식 메뉴나 메뉴 영역 자체 스크롤을 통해 11개 링크 모두 keyboard와 touch로 접근할 수 있어야 한다.
- 본문 skip link와 `quant-research-theme` 및 기존 theme key migration을 유지한다.

차트
- 기존 차트 유형·패널·축·범례·계열과 표의 열·순서·결과 구조를 유지한다. 다음 상호작용은 기존에 해당 기능이 있거나 도메인상 필요성이 확인된 비교 계열·날짜 축에만 적용하며, 공통 디자인만을 이유로 새 기능이나 특정 프로젝트의 차트 형태를 강제하지 않는다.
- 계열 hover/focus preview와 click/tap/Enter/Space pin을 지원하고 비활성 계열을 흐리게 표시한다.
- 선택일 정확값·단위와 날짜 이동·최신일 복귀·ArrowLeft/ArrowRight/Home/End를 지원한다.
- 정확값 readout은 plot 위에 겹치는 absolute overlay가 아니라 plot 밖의 고정 행에 둔다.
- custom readout이 있으면 SVG native title tooltip과 모든 시점 값 label을 동시에 표시하지 않는다.
- 끝 라벨용 gutter와 collision rule을 두고 선·점·신호·축·라벨끼리 겹치지 않게 한다.
- 모바일 readout은 가로 스크롤 canvas 밖에 유지하고 차트만 내부 스크롤한다.
- 차트 탐색 상태가 분석 입력·공식 결과·URL·저장 설정을 바꾸지 않게 한다.

진행 순서
1. 실제 저장소·공개 화면·데이터 계약과 현재 worktree를 감사한다.
2. 수정 금지 파일과 허용 프론트엔드 범위를 고정한다.
3. 수정 전 대상 화면의 computed font-size·font-weight·line-height·간격·scrollHeight와 상위 메뉴 inventory를 저장하고 공통 권장 범위에 대조한다.
4. visible copy inventory를 만들고 중복·구현 설명·행별 장문을 제거하거나 하나의 닫힌 운영 상세로 이동한다.
5. 결과 우선 정보 구조, 공통 시각 밀도, 11개 상위 메뉴와 필요한 차트 충돌 방지안을 구현한다.
6. 기존 계산·데이터 테스트와 신규 UI 회귀 테스트를 실행한다.
7. 데스크톱과 390px 모바일의 라이트·다크를 확인한다.
8. PR·CI·Pages 배포 후 공개 URL을 다시 읽어 검증한다.

검증
- protected diff가 비어 있어야 한다.
- 기존 Python·데이터·정적 계약 테스트가 통과해야 한다.
- 공개 DOM에 중복 설명 0건, 중립 사유 1회 이하, 구현·재계산 설명 0건인지 확인한다.
- 일반 규제·면책·제한·한계·출처·fallback·자동화 상세가 기본 화면에 반복되지 않고 하나의 닫힌 운영 상세로 통합됐는지 확인한다.
- 계산된 글자 크기·굵기가 공통 권장 범위와 상대 위계를 따르고 `800` 이상 굵기가 브랜드·eyebrow·소수 핵심 강조 밖에 반복되지 않는지 확인한다.
- 같은 데이터·viewport에서 불필요한 설명과 여백으로 `scrollHeight`가 증가하지 않았는지 확인한다.
- 상위 메뉴 링크가 정확히 11개이고 registry와 label·순서·URL이 일치하며 `aria-current="page"`가 정확히 1개인지 확인한다.
- active/muted 계열, 날짜 선택, 키보드, 44px touch target, 페이지 overflow를 확인한다.
- readout과 plot·축·직접 라벨의 bounding box가 데스크톱·모바일에서 겹치지 않아야 한다.
- 수정 전후 차트 type·series·axis·legend와 표 column/order를 대조해 공통 디자인과 무관한 구조 변경이 없는지 확인한다.
- 기존 색 토큰과 프로젝트별 의미색이 유지되는지 확인한다.
- 공개 자산과 최신 main이 일치하고 데이터 기준일·상태가 정상적으로 읽혀야 한다.

완료 보고
- 바뀐 UI와 제거한 반복 문구를 요약한다.
- 공통 기준과 일치시킨 타이포그래피·굵기·세로 밀도와 11개 상위 메뉴 검증 결과를 적는다.
- 유지한 프로젝트 고유 색감·차트·표·결과 구조를 적는다.
- Python·분석·JSON·workflow 보호 파일이 바뀌지 않았다는 증거를 별도로 적는다.
- 테스트, PR, 배포 실행, 공개 URL을 제공한다.
```

## 적용 원칙

이 프롬프트는 v1.2 파일럿 적용 이력이다. 현재 프로젝트별 plan-goal의 시작점은 [Quant Research Web Design Prompt](web-design.md)다. 어느 한 프로젝트도 복제 기준이 아니며, 도메인에 없는 신호·날짜·입력을 새로 만들지 않는다.
